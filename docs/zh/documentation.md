# 文档维护

文档面向使用者、集成者和维护者。按读者要完成的任务组织页面，提供清晰步骤与相关文档入口。

## 页面职责

- README：项目用途、运行条件、首次启动及文档入口。
- 快速开始和功能页：完整步骤、输入、结果、失败恢复和权限边界。
- 架构与接口页：模块职责、数据流、契约、状态与错误行为。
- API 引用：绑定现有 Python 符号，避免手抄会漂移的签名。
- 测试与贡献说明：运行环境、命令、目录及开发流程。

## 修改规则

英文路径与 `zh/` 中文路径成对维护，每页保留语言切换。命令、标识符、配置字段和版本必须与源码一致。先核对实现、调用方和测试，再描述行为。每段说明一个主题，步骤使用明确动作，删除过期结论和没有依据的完成声明。

公开模块入口、接口和关键状态变化应有简短职责注释。Python 沿用英文文档字符串，前端沿用所在模块的中文注释；第三方许可证文字保持原文。

报告和截图放仓库外。产品文档只保留可重复的操作、明确的限制及维护入口。功能变更时更新对应英中页面及 `mkdocs.yml`，见[测试与交付](testing.md)。

## 检查

```bash
python scripts/check_docs.py
python -m mkdocs build --strict
```

上述命令检查链接、双语配对和 API 引用。发布前阅读 README、按安装步骤操作，并查看构建页面的排版和导航。
